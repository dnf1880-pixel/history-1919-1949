# 有些历史不该忘 · 1919—1949 中国近现代史关键事件

一个纯静态、可离线运行、PC 与移动端自适应的历史教学互动网页。
七个关键事件独立成页，首尾相接、顺序可连续浏览；首页带沉浸式打字机开场与全站时间轴总览。

**打开方式**：双击 `index.html` 即可用浏览器打开，**无需联网、无需服务器、无需构建步骤**。
（若浏览器对 `file://` 下的本地脚本有限制，用任意静态服务器托管根目录亦可，例如
`python -m http.server 8000`。）

## 三、技术路线

### 3.1 数据驱动，从根源杜绝死链

`assets/js/data.js` 是全站**唯一真相源**，声明四张表：

```js
window.SITE          // 站点标题、副题、年份范围、首页文件名
window.STAGES        // 三阶段：觉醒 / 战斗 / 建国（含色系与年份区间）
window.EVENTS        // 七个事件：id / order / file / date / title / place / stage / 摘要 / KPI
window.PREFACE       // 开场卷首语（9 段）
window.LEARNING_PATH // 学习路径四步
```

导航栏、移动端抽屉、时间轴、事件卡片、上下篇切换**全部由 JS 读取上表渲染**，HTML 里不手写任何跨页链接。
新增或调整事件只需改 `data.js` 一处，全站同步生效。

### 3.2 相对路径双模式（首页 / 子目录自适应）

`site.js` 检测当前是否位于 `events/` 子目录，统一走封装函数拼路径：

```js
inEventsDir ? '../index.html' : 'index.html'          // 返回首页
inEventsDir ? '01-wusi.html'  : 'events/01-wusi.html' // 事件页互链
(inEventsDir ? '../' : '') + 'assets/' + p            // 静态资源
```

七页与首页共用同一套 `site.js`，双模式均已真机验证无 404。

### 3.3 零外部依赖（可完全离线）

- **不使用任何 CDN**、不加载任何网络字体、不引用任何音频/图片文件。
- 所有插图与史料图为**手写内联 SVG**。
- 所有音效由 **WebAudio 实时合成**（`OscillatorNode` + 白噪声 `AudioBuffer`），音频体积为 0。
- 双击 `index.html` 即可运行，断网、内网、U 盘拷贝场景均正常。

### 3.4 音频策略

浏览器要求音频必须由用户手势解锁，因此：

- 默认**静音**；首页与开国大典页均提供"开启声音"按钮，点击后调用 `Sound.unlock()` 恢复 `AudioContext`，按钮 `aria-pressed` 同步状态文字。
- 未开启声音时，打字与炮火只是**不出声**，动画流程不受任何影响。

### 3.5 响应式断点

| 断点 | 变化 |
|---|---|
| `max-width: 860px` | 导航转汉堡抽屉；开国大典页城楼 SVG 改贴底裁切、宣告文字收入首屏 |
| `max-width: 900px` | 事件页 hero 双栏转单栏；时间轴出现"左右滑动"提示 |
| `max-width: 720px` | KPI 数字区改为堆叠；**移动端字体预设生效**（见 3.7） |
| `max-width: 640px` | 开国大典页控制按钮收紧 |
| `max-width: 560px` | 定位器收紧（隐藏操作提示、标签缩一号） |
| `max-width: 400px` | 字号再降一档，守住可读下限 |
| `max-height: 520px` | 横屏手机：抬高首屏最小高度，避免内容被裁 |

已验证尺寸：1440×900（桌面）、768×1024（平板）、390×844、360×640（手机），均**无横向溢出**。

### 3.6 可访问性与无障碍

- 系统字体栈（`PingFang SC` / `Microsoft YaHei` / `Songti SC`）；桌面正文字号 ≥ 14px，移动端 ≥ 15px（见 3.7）。
- 关键状态不**仅**以颜色区分，同时有文字说明与形状差异。
- 导航抽屉支持 `Esc` 关闭、点击外部关闭；汉堡按钮带 `aria-expanded` / `aria-controls`。
- 定位器的站点组带 `role="radiogroup"` / `aria-checked`，支持键盘 `←` `→` 逐站切换。
- 小测得分区带 `aria-live="polite"`。
- 支持 `prefers-reduced-motion: reduce`：关闭云层横移、旗帜飘扬、光标闪烁等持续性动画。

### 3.7 移动端字体预设（`mobile.css`）

**为什么单独一个文件**：`base.css` 与 `design.css` 里各自都有 `max-width` 媒体查询，两者特异性相同，**后加载的文件胜出**。早期把字号预设写在 `base.css`，结果被 `design.css` 里那些 11—13.5px 的小字规则覆盖（实测 390px 下正文仍是 15.5px，预设形同失效）。因此该层独立成文，并在 `<head>` 里放到所有样式表**之后**，作为移动端排版的最终决策层。

**预设依据**（小屏阅读的三条现实约束）：

1. 手机视距约 25—30cm，比桌面近得多 → 正文字号要放大、行高要更松；
2. 中文在小字号下笔画会糊，字号下限比西文高 → 正文不小于 15px；
3. 屏幕窄、每行字数少 → 两端对齐会产生「河流」空隙，改左对齐。

**实际取值**（390×844 实测）：

| 元素 | 桌面 | 移动端 |
|---|---|---|
| `body` 根字号 | 16px | **17px**（≤400px 时 16.5px） |
| 正文段落 `.block__body` | 15.5px | **16.5px** |
| 名词表 | 13.5—14.5px | **15.5px** |
| 图注 / 人物说明 / 时间线说明 | 12—13.5px | **15.5px** |
| 小测题干与选项 | 14—15px | **15.5px** |
| 定位器读出文字 | 14.5px | **15.5px** |
| 区块标签 `.block__label` | 11.5px | **12px** |
| 正文对齐方式 | 两端对齐 | **左对齐** |

> 维护提示：新增组件若带小字号，请把该选择器一并补进 `mobile.css`，否则移动端会掉回桌面字号。
